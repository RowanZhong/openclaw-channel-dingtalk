# 通用评价 HTTP 上报实施与验收

基线：6da056b；目标：旧版 OpenClaw 2026.7.1-2。保持原有卡片与权限规则。

- 只上传发生过有效评价的一问一答，保存最新状态；撤销也同步。正文缺失、校验失败、暂缓采集分别表达。
- 源评价 JSON 同次保存单调版本和上报目的地标识。后台独占自己的耐久 outbox；主线程不等待网络、不解析大转录、不传递全文。
- 每实例最多一个按需 Worker。小型元数据发现分批异步进行，宿主繁忙/事件循环延迟/内存压力时退让；请求、响应、正文、读取、任务和队列均设上限。
- HTTP 目的地管理员配置，HTTPS 默认；Bearer 使用宿主 SecretInput；禁重定向，不在日志输出正文或凭据。
- 持久化请求后才发 HTTP；明确 schema、稳定记录身份、单调版本和持久化 ACK；重试及重启可重复发送，接收端按最新版本幂等写入。
- 交付 OpenAPI、接收端契约、OceanBase 4.2.5.7 MySQL 参考 DDL/事务流程、故障和容量说明。公司数据库无连接信息，不声称完成真实 OceanBase 验收。
- 测试：配置、本人评价、并发/撤销、不确定内容、错误 ACK、网络超时/重定向、断网恢复、重启、工作线程终止和前台退让；全量回归、运行包资产与文档构建。
- 真机：小钉真实点赞点踩/撤销 → 本机专用 HTTP 验收接收器，核对问答与最终状态；故障重试和重启补传。完成后恢复日常网关。
- 压力：主线程事件循环 A/B、超时接收器、大转录、积压、前台活动抢占；目标 Pod requests=50m/100M, limits=4 CPU/8G。经用户授权安装临时隔离 Lima/Ubuntu/K3s，在相同 requests/limits Pod 完成测试，完成后删除环境。受测为真实上报模块与合成前台探针，不冒充公司生产 LLM 延迟或 OceanBase 性能。
