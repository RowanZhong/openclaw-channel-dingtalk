# DWS 消息主题与固定模板答复设计

适用版本：助手 0.7.0，OpenClaw 2026.7.1-2 / 2026.8.1。状态：已实现；两版核心真机验收完成，详见 docs/assets/dws-topic-validation.json。

## 产品行为

来源仍由私聊、群 @本人、额外发送者三个规则组取并集。主题只能进一步限定已允许来源，不新增 DWS 订阅或常驻进程。主题识别默认关闭，升级保留现有关键词自动回复与员工选择。

员工入口：监听范围 → 消息主题。模式包括“明确未命中后沿用原有流程”和“只关注指定主题”。未知、冲突、错误不是不匹配，必须保留可修改、重新拟稿的待判断记录。只关注模式没有启用规则时保留待判断，不静默丢弃所有来信。

每条主题包含名称、来源及对象、问题描述、典型问法、排除情形、固定正文和处理动作（自动、确认、仅整理）。自动授权包含期限和冷却。到期后主题仍保留，但改为模板待确认。停用或删除规则后按剩余主题和未命中策略处理；关闭主题识别恢复原有流程。

## 判类与发送边界

- 先验证来源、个人开关、暂停和“不处理”，再筛选可用主题；一条消息一次比较该来源下的所有启用主题。
- 使用宿主无工具 completion API，复用当前配置的 Agent 选择逻辑；不启动 Agent 执行、不读取工作区、邮件或私人记忆。
- 模型只返回 outcome、ruleIds、coversWholeMessage、reason。严格 JSON、白名单字段、已存在的规则 ID、唯一匹配且完整覆盖。模板字面内容由服务端存储读取，模型不能提供收件人或发送正文。
- 排除情形、复合问题、含糊指代、多条匹配、解析失败、超时、队列溢出转本人判断。不依赖模型自报置信度；语义误判风险仍存在，规则模拟和人工审核不能证明对所有输入完全准确。
- 主题自动答复与已有关键词授权命中不同正文时，转人工。显式 nonmatch + fallback 才继续旧关键词流程。
- 发送前再次核对主题开关及 revision、来源、固定正文、授权期限、规则冲突、全局每小时 30 条和每规则每会话冷却。只整理/不处理优先于自动授权。
- 每条记录绑定来源消息、原会话、偏好版本、主题版本和发送状态；发送前持久化 claim，未知结果不自动重发。
- 延续现有同一会话最新来信使旧草稿失效的策略；即使后续来信最终被主题过滤，也不复活旧草稿。

## 运行与恢复

主题设置保存在既有 SQLite settings 键中（version 1 的向后兼容可选字段 topics），不修改 openclaw.json。主题独立 revision 避免单纯调整提醒就使判类结果失效。修改主题后旧批准版本不能直接发送；本人重新拟稿后按当前版本确认。

判类后台串行执行，最多 32 个运行或排队任务；排队最长 30 秒、单次调用超时 15 秒，无自动模型重试。宿主若忽略取消信号，未结束调用期间不再启动新的判类。消息接入和 Stream ACK 不等待判类，主会话执行通道不被占用。插件启动没有新增模型请求，现有 DWS 身份检查方式不变。

重启把 classifying 恢复成 topic-review，sending 恢复成 unknown，禁止自动重试发送。filtered 保留本地记录和去重指纹、不进待回复清单，按现有 30 天终态清理策略清理。已收消息仍需要本地判类，不能宣称 DWS 只投递命中主题的内容。

## 卡片与兼容

不改卡片模板、变量契约和社区插件。复用 title、description、form、6 个 button/action 与 card_expires_note，新增六个短向导页：来源、主题定义、处理方式、模拟试判、期限频率、完整确认。仅最终服务端摘要保存规则；自动授权至少完成一条明确匹配的模拟试判，修改定义/正文后清除旧试判结果。模拟不发送、不改变授权到期时间，且明确不验证实际来源订阅及其他规则冲突。

每页不超过 4 个表单字段和 6 个按钮。员工既可管理规则，也可停用、删除、查看及重新编辑。编辑自动规则的最终确认重新计时；界面明确显示重新授权。

## 验证要求

两版分别执行完整自定义插件测试、宿主 completion 集成、动态表单契约、既有回归检查。真机覆盖主题创建及试判、不同问法自动发送同一正文、故障排除人工回退、群内引用、只关注模式的未命中过滤、冷却和规则停用。模板确认/仅整理、fallback、含糊/复合、冲突和重启安全等分支由自动化回归覆盖；不把这些算作好友真机结果。保留脱敏结果，结束后复原原始 Gateway 配置与员工状态。
