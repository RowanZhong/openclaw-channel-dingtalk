# 定时自动收集

配合 `dingtalk-form` Skill，可以让 OpenClaw **内置 cron** 按计划发送钉钉交互表单。首次确认内容和对象后，到点直接发正式表单，不再弹设计向导，也不要求发起人在线。

此功能需要包含 `dingtalk_form_schedule` 的插件版本及配套 Skill。本地实现基于 OpenClaw 2026.8.1 的 cron script payload；不是仅靠提示词调用原来的即时表单工具。

## 适用场景

| 场景 | 典型收集内容 | 示例指令 |
| --- | --- | --- |
| 信息收集 | 办公物资、培训需求 | 每周一上午 10 点，向行政群的小林和小陈收集本周物资需求，1 小时截止 |
| 需求调研 | 客户痛点、业务影响、紧迫程度 | 每周五下午 3 点，向销售群的三位负责人收集本周客户反馈，2 小时截止 |
| 项目协同 | 交付时间、依赖、资源缺口 | 每个工作日下午 4 点，向项目群各已确认负责人收集交付风险，30 分钟截止 |
| 进度跟踪 | 已完成事项、下一步、当前阻碍 | 每个工作日下午 5 点，向研发群的小林和小陈收集今日进展、明日计划和阻碍，30 分钟截止 |

以上是周期性收集与逐轮汇总，不包含跨周台账、趋势分析、自动分派任务等完整项目管理能力。

## 使用流程

例如在机器人私聊中说：

> 每个工作日 17:00，在项目群让小林和小陈填写今日进展、当前阻碍和明日计划，30 分钟截止。按北京时间执行，结果回这里，请建立定时收集。

机器人核实对象，必要时补齐设置，然后创建任务。给出完整要求时不强制引导；只说用途时，可以先通过设计卡补齐并确认一次。配置完成会告知任务和下一次执行时间。

以后每次到点：

1. cron 直接执行确认后的模板，向目标群或个人投放一张新表单。
2. 仅确认名单内的人可填写，其他人不能提交。
3. 收齐首次回应就提前结束；否则等到本轮时限。
4. 插件把结果直接回传到首次发起的会话，标题、整体状态、逐人状态和答案使用固定列表格式。

群聊中发起，结果回原群；私聊中发起，结果回原私聊。机器人必须能向投放对象和回传会话主动发消息；群投放前需加入目标群。

## 触发与管理

- “帮我设计一张需求表”触发一次性引导，不创建周期任务。
- “把这份完整表单直接发给小林”触发快捷创建。
- “每天/每周/明天某时自动收集”触发定时配置；应明确日期、时区和收集有效期。
- “查看我的定时收集”查询模板，再检查对应 cron 任务的启用状态和运行记录。
- “暂停以后的进展收集”禁用 cron；“恢复”启用原任务。
- “删除这个定时收集”撤销模板并删除 cron 任务。
- “取消正在收集的这一张”只结束当前表单，不删除未来计划。

管理员也可以通过 `openclaw cron list --all` 查看，通过 `openclaw cron runs --id <jobId>` 检查记录。不要修改生成的 script、Agent、会话类型或重置其 state；只改执行时间可使用原生 cron 修改 schedule。改题目、名单或有效期，应重新确认并建立新模板。

## 边界与异常

- **固定名单**：保存配置时核实的成员快照。暂不支持每轮自动查询并纳入新加入的群成员。
- **时间**：每张整数 1–1440 分钟；未指定时默认 5 分钟，配置时明确告知。周期重复不代表同一张表长期开放。
- **人数**：单张 1–50 人，是当前插件实现上限。
- **重叠**：上轮还未结束，本轮跳过，不覆盖原表单。
- **重复触发**：同一轮重复执行不会再发卡；投递状态不确定时阻止自动重发，由原发起人确认放弃异常轮次后恢复原计划。
- **权限变化**：创建和执行都检查原发起人及目标群的访问策略；配对模式读取原生账号配对记录。机器人被禁用、原账号被替换或发起人失去授权时，停止该轮并记录失败；回传前也会复查授权。
- **重启**：计划和模板保留；已发出的未完成表单终止，旧答案不恢复。发卡中途重启留下的不确定轮次需要发起人确认恢复；已完成收集的待发汇总另行保存，可以补发。
- **回传**：直接发送结果，不把填写内容作为新用户指令交给模型。暂停计划不影响已发出的表单回传。
- **状态区别**：cron 的执行成功代表本轮发卡或跳过成功，成员结果稍后回传；可通过模板 `lastRun.deliveryError` 检查最近一轮回传失败，通过 `resultDeliveries` 查看各轮未完成投递，后续轮次不会覆盖旧的待发结果。修改 cron 时间后，以原生 cron 的配置为准，模板记录保留最初时间设置。

如宿主禁用了 cron/script 或拒绝创建权限，机器人应明确说明，不擅自修改全局权限。部署前应核实主动投递权限；模板不保存 access token、会话 webhook 或聊天历史。

## 实现约定

`dingtalk_form_schedule` 提供 `prepare`、`bind`、`list`、`disable`、`recover`、`retry_result` 和 cron 专用的 `run`。创建顺序为：保存确认模板 → 原生 cron 创建禁用任务 → 绑定真实 jobId → 原生 cron 启用并核实。未完成全部步骤不算启用成功。

即时表单工具 `dingtalk_ask_user_question` 仍要求真实钉钉会话。定时执行使用绑定的 cron 会话及 Agent 校验，不借用历史入站消息。详见 [表单互动卡片](form-interactive-card.md)。

## 异常时如何继续

**发卡中断**：在原发起会话说“查看我的定时收集”。机器人会指出状态不确定的轮次。确认“放弃这一轮，恢复后续计划”后，原计划可以继续；不会重新投放可能已送达的卡片。暂停过的 cron 仍需按需恢复。下一次触发可能只对齐已放弃的轮次，随后触发恢复正常投放，不需要更换计划或重置序号。

**只收到部分汇总**：说“补发这次收集还没发完的结果”。插件保存了完整汇总和已确认的发送位置，只从未确认的部分继续，并固定回传原会话。如果网络中断造成某一条是否送达无法判断，机器人会先说明该条可能重复，再请求明确确认；已确认成功的片段不会重发。仍在发送时不能并发补发。

回传前及每条发送前均复查权限。完整送达后清除本功能保存的汇总正文，仅保留最近 20 轮完成标记；未完成投递会跨重启保留，后续轮次不会覆盖。此机制针对**已经结束的收集结果**，不恢复重启前仍在填写的答案，也无法恢复旧版本未保存的失败汇总。
